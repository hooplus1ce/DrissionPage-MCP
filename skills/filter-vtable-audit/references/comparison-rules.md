# 比对判定规则与陷阱（comparison-rules）

## 一、字段/列计数口径

### 筛选区（查询区）字段计数
- 一个筛选字段 = 「字段名」+「操作符」+「值控件」三元组。以 **值控件** 或 **操作符下拉** 数量为准复核字段数。
- 值控件类型：
  - `input.ant-input-sm` 文本框 → 文本筛选；
  - 无 a11y name、class 含 `selectUid*` 且外层 `div.legions-pro-select` 的 combobox → **值下拉**（必须取待选值做匹配）；
  - `input.ant-calendar-range-picker-input` → 日期区间筛选。
- 排除：查询/设置/重置/收起▲/更多(列设置)按钮、导出、分页控件(`li.ant-pagination-*`)、工具栏。

### VTable 列计数
- `vtable_analysis`(full) 给出 `analysis.columns[]`，取 `title`+`field`。
- **系统/操作列不计入业务列**：
  - `_vtable_checkbox`（复选框全选）
  - `_vtable_series_number`（序号）
  - 操作列（标题"操作"，如 field `_op`，内容为日志/编辑等行按钮）
- 业务列 = 其余列。筛选区与业务列做对齐比较。

## 二、名称一致性判定
- 同一业务语义（可经 field 名交叉验证，如筛选标签"销售区域名称" ↔ 列 `field=area` title"销售区域"）显示名不同 → **命名不一致缺陷**。
- 一个字段名在两边都出现且语义相同 → 对齐（22 对等）。

## 三、列单元格值 ⊆ 下拉待选值（严格覆盖，C ⊆ D）
用户口径（勿自行放宽）：**列表对应列字段下每个单元格内容都必须被下拉待选值集合包含**。
- 单元格值 `3`(数字) vs 待选值 {1级,2级,3级,4级,5级} → **不匹配**（类型/文本双不一致）。
- 单元格值 {未审批,已审批} vs 待选值 {待审核,已审核} → **不匹配**（零交集，字典文案两套）。
- 单元格 {是,否} vs {是,否} → 匹配 ✅。
- 布尔列若单元格为空串但列存在，归入"列数据为空"观察项（需人工确认是数据未填还是渲染缺失，勿直接定性）。
- 无对应列的下拉筛选字段（如"是否允许同生产基地拆分"）与无筛选项的列（如 splitAllowed"是否允许拆单"）→ 属于配置不同步缺陷，不做值匹配。

## 四、常见根因推断（供报告"影响分析"引用）
- 值显示为原始编码（数字/代码）而筛选下拉用翻译文案 → 列表列渲染缺字典翻译（format 未配置）。
- 同一状态字段列/筛选文案不同 → 配置了两套字典 value/text 或新旧字典并存未迁移。
- 筛选独有字段无列表列 / 列表独有列无筛选 → columns 配置与查询表单 queryItems 未按同一业务实体同步维护。
- 判断时以证据为准，措辞用"疑似"，避免主观定责。

## 五、操作陷阱（本环境实测踩坑）
1. **大输出持久化**：`vtable_analysis`(full, include_values) 结果可能 >50KB → 被存到 tool-results 目录 `.txt`。用 Read 配合 python `json.loads` 提取所需字段即可，勿整读。
2. **截图返回 base64 巨大**（>20 万字符）也会被持久化；若仅作证据存档，直接调用后从 JSON 提取 `path`，不要 Read 图片本体（多模态可能不支持/浪费 token）。
3. **ui_screenshot 传 frame+坐标会报错**（viewport 截图不允许带 frame）；要么用元素定位（css 定位 iframe 标签），要么顶层坐标不带 frame。
4. **a11y 双节点**：同字段的 control 与 combobox 各计一个 ref，勿重复计数。
5. **操作符下拉 vs 值下拉**：都叫 combobox，按 a11y name 区分——有"包含/等于/介于"名字的是操作符，无名字且 css 带 `selectUid*` 的是值下拉。
6. 值下拉多次点击取证时**上一个下拉自动被关闭**，无需手动关；全部取证后点击页面空白处清浮层。
7. **浮层遮挡后续下拉**：某行下拉展开后（尤其 bottomleft 弹出且纵向高 250px 的字典下拉，如部门/物料类），会盖住下一行同一 x 坐标的值下拉，导致下一轮 ui_click 超时。遇点击超时且页面存在 visible_overlay 时，先点击页面空白处（无控件坐标，如工具条空白区）关闭浮层，再继续点下一个下拉。
8. 多 iframe：业务 Tab 若不止一个，先 `ui_page_context` 看 `active_iframe` 再操作，防止打到其它 Tab 的 frame。
